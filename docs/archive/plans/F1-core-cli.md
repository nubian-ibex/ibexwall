# F1 — Core daemon + minimal CLI

Goal: deliver the privileged core (`ibexwalld`) with the full change
engine, plugin supervisor and event bus, plus a complete `ibexctl`, all
verified inside VMs. Nothing in F1 touches the developer host: the
daemon runs unprivileged under `IBEXWALL_ROOT` with fakes locally, and
exercises real systemd/polkit/nftables only inside the QEMU VMs.

Status: awaiting approval.

## Preconditions

- [x] F0 accepted (2026-11-01)
- [x] Host tooling for VM tests installed (qemu-img, genisoimage)
- [ ] Spike verdicts (S1-a, S1-b) recorded as ADRs before the
      corresponding code lands

## Scope decisions (need reviewer awareness, not separate approval)

- **Op executors in F1**: the engine validates and can execute
  `file.write`, `file.remove`, `systemd.unit`, `sysctl.set`,
  `nft.fragment` (JSON via `nft -j`, `nft -c` precheck) and `exec`.
  The adapter-style ops (`firewall.adapter`, `dns.backend`,
  `flatpak.override`, `snap.interface`, `browser.policy`, `nm.setting`,
  `package.install`) get validators + inverse metadata now and land
  executors with their phases (F3/F4/F5). Acceptance criteria for F1
  only require file/unit/sysctl paths.
- **SQLite linkage**: `rusqlite` with `bundled` in dev/CI now; system
  linkage decision is a packaging concern (F10).
- **Org layer**: precedence and locks are implemented and tested with a
  local fixture; `com.ibexwall.Policy` itself is F11.
- **Dev plugin signing**: `--dev-key` minisign-style key generated by
  xtask for tests; the official embedded key arrives with the release
  pipeline (F10).

## Milestones (each lands green: fmt, clippy, nextest, deny, no drift)

### M0 — Spikes (timeboxed, results become ADRs)

- **S1-a (1d) — varlink implementation.** Candidates: `zlink`
  (async-first, tokio, codegen; All Systems Go 2025), the official
  `varlink` crate (sans-io core), or hand-rolled framing over tokio.
  Criteria: `more`/`continues` streaming, named errors, maintenance
  health, permissive license, audit surface, fit with our
  proto-first/IDL-generated workflow. → ADR-0024.
- **S1-b (0.5d) — caller identity + polkit subject.** Verify
  `SO_PEERPIDFD` (kernel >= 6.5; host and VM are 6.19) and whether the
  VM's polkit accepts pidfd subjects; fallback is `unix-process` with
  pid + start time. Never authorize by bare PID. → ADR-0025.

### M1 — ibexwall-sys: the testability seam

- Traits `Fs`, `Systemd`, `Sysctl`, `Polkit` (+ `Clock` for
  time-dependent logic) with real implementations (argv only, no shell;
  `IBEXWALL_ROOT` prefixing) and recording fakes.
- Unit tests for the fakes/real split; `ProtectHome`-style invariants
  documented for the real ones.

### M2 — Core skeleton

- `ibexwalld` binary: tokio runtime, socket activation
  (`LISTEN_FDS`), direct bind under `IBEXWALL_ROOT` for dev/tests;
  varlink server per ADR-0024; `GetInfo` (api = 1).
- Per-method polkit authorization (ADR-0025) with the action map from
  `names`; `PermissionDenied` mapped to exit code 3 on the CLI.
- Structured logging: `tracing` + `tracing-journald` (SYSLOG_IDENTIFIER
  per binary; `IBEXWALL_PLUGIN`/`IBEXWALL_TX` fields), no secrets.

### M3 — Config layers, locks, drift

- Layers `default < profile < user < org` from TOML under
  `/etc/ibexwall` (+ `plugins.d/`, `profiles.d/`); strict parsing,
  `deny_unknown_fields`, size limits.
- Lock enforcement on every write path (API/CLI): `Locked {keys,
  source}` → exit code 4.
- State fingerprint (relevant config + manifests) feeding plan
  staleness; drift checker schedules a finding (reapply/adopt flows are
  UI-facing, data model now).
- Unit tests: merge matrix, lock precedence, unknown-key rejection,
  proptest for the TOML parsers.

### M4 — State and audit

- SQLite (WAL) with a small embedded, versioned migration runner
  (~hand-rolled; no extra dependency); tables per spec §4.4
  (transactions, snapshots, settings_layers, findings, events,
  audit_log, ...).
- Audit chain: `hash = SHA-256(prev_hash || JCS(entry))` (serde_jcs +
  sha2), `ibexctl audit verify` validates; append-only discipline;
  entries carry actor (`user:<uid>`, `system`), plugin, tx, op digest,
  result.
- Unit tests: chain continuity, tamper detection, actor attribution.

### M5 — Change engine (highest coverage target: >= 90%)

- Full lifecycle: planned → approved → applying → applied(pending_confirm)
  → committed, with rolled_back/failed; single global queue; idempotent
  ops; expiry (10 min) + staleness replan.
- Validation of each op against manifest `[privileges]` (paths,
  units + actions, sysctl keys, exec allowlist argv pattern, nft prefix)
  → out-of-manifest ops refused (acceptance criterion).
- Snapshots: prior content/mode/owner, unit state, sysctl values
  (runtime + file), manifest with checksums, under
  `snapshots/<tx>/`.
- Atomic writes: tmp + fsync + rename, no symlink following
  (`openat2` via rustix, `RESOLVE_NO_SYMLINKS`).
- Confirm window (default 60 s) with auto-rollback on timeout; CLI
  `--confirm-timeout`.
- Crash recovery: on startup, revert any `applying`/`pending_confirm`
  and notify (event + journal).
- **S1-c (1d) — transient-unit executor spike** (`StartTransientUnit`
  with `ReadWritePaths` = exact transaction paths) → ADR-0026 with
  adopt/defer recommendation; in-process executor is the default until
  then.
- Tests: state machine unit tests; apply/rollback byte-for-byte with
  fakes; property tests on op validation; chaos (kill -9 mid-apply,
  unconfirmed timeout) as VM scenarios in M9.

### M6 — Plugin supervisor + dev.echo

- Discovery (`/usr/lib/ibexwall/plugins/<id>/plugin.toml` +
  `plugins.local`), manifest validation from proto, dev-key signature
  check, compatibility gates.
- Unit generation from `[sandbox]` (DynamicUser, ProtectSystem=strict,
  NoNewPrivileges, CapabilityBoundingSet, RestrictAddressFamilies,
  SystemCallFilter) + `systemd-analyze security` note <= 3.0 recorded in
  capabilities matrix.
- Per-plugin varlink client (`Describe/Check/Plan/Verify/Monitor/
  Reconcile`), per-call timeouts, restart + "degraded" marking.
- `plugins/dev.echo`: a real plugin exercising every op type — valid
  plans, out-of-manifest plans (for refusal tests), slow ops (for the
  kill -9 window), and a monitor stream for events.

### M7 — Events

- Event bus in core (`Subscribe` with `more`/`continues`), sources
  tagged, `untrusted` fields carried structurally; ring buffer with
  retention defaults (7 d detailed) scheduled.

### M8 — ibexctl

- Full command surface (spec §4.11): status, plugins
  {list,info,enable,disable}, check, findings, plan, apply, confirm,
  rollback, history, audit verify, events [--follow], config export/
  import, `--json` everywhere (schema-versioned), exit codes
  0/1/2/3/4/5/10.
- `clap` + `clap_complete` + `clap_mangen`; man/completions generated
  via `cargo xtask docs` into `packaging/`.

### M9 — VM integration + chaos suite

- `xtask vm-test --phase f1`: provisions the VM over ssh (release
  binaries, units, polkit policy, sysusers/tmpfiles, dev plugin + key)
  and runs the acceptance scenarios as scripts:
  1. plan → apply → verify → commit writes the drop-in; rollback
     restores byte-for-byte (sha256 before/after);
  2. `kill -9` the daemon mid-apply (dev.echo slow op) → automatic
     rollback on restart;
  3. network-risk tx without Confirm reverts after the (shortened for
     test) window, default 60 s proven once;
  4. unprivileged VM user gets PermissionDenied (exit 3);
  5. `audit verify` detects a tampered entry;
  6. out-of-manifest op refused.
- Stretch: hard VM reset mid-transaction (kill QEMU) then boot and
  verify recovery.
- Matrix: Fedora first; Ubuntu/Debian/Arch images wired in this phase's
  harness (smoke-level) to catch distro drift early, full matrix runs
  from F2.

### M10 — Docs and closeout

- Threat model update (mandatory review point: socket, polkit subject,
  engine, supervisor now exist), `docs/capabilities-matrix.md` v1,
- ADRs 0024-0026 from spikes, STATUS.md update, phase report.

## Deliverables (spec §15 F1)

`ibexwalld` (socket activation, varlink, polkit per pidfd, config
layers, SQLite + migrations, chained audit) · complete change engine
(snaphots, timed confirmation, crash recovery, drift) · plugin
supervisor (discovery, dev signature, generated units, timeouts) ·
event streaming · `ibexctl` full surface · `dev.echo` plugin ·
transient-executor spike ADR.

## Acceptance criteria (all in VM, scripted in M9)

- [ ] plan → apply → verify → commit writes the drop-in; rollback
      restores byte-for-byte
- [ ] kill -9 mid-apply → automatic rollback on restart
- [ ] network tx without confirm reverts at the deadline (default 60 s)
- [ ] unauthorized user receives PermissionDenied
- [ ] audit verify detects tampering
- [ ] out-of-manifest operation refused

Also: fmt/clippy/nextest/deny/schemas-check green; coverage >= 80%
core crates, >= 90% engine + op validation.

## Risks

- `zlink`/`varlink` crate maturity (streaming edge cases) → spike with
  written criteria; hand-rolled fallback is bounded (~500 lines).
- polkit pidfd subject support varies by distro version → fallback is
  pid+start-time; spike on the actual VM polkit.
- Phase size: engine + supervisor + CLI in one phase → milestone-gated
  commits, each independently green; adapter-op executors explicitly
  deferred (scope decision above).
- Transient executor may not be viable on all distros → default stays
  in-process with strict path validation; ADR decides.

## Out of scope (explicitly)

UI/TUI, posture plugins, DNS resolver, eBPF, MCP, packaging for distro
repos, org-policy interface (F11), firewall/DNS adapters beyond
validators.

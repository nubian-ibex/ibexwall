# v0.2: turning protections on, and the first run

Status: started in autonomous mode (2026-11-09) after v0.1.1 was built;
the maintainer reviews before anything is released. Backlog: B-04, B-06
(planning/13). Decision: ADR-0046.

With v0.1.1 a person can change the machine. What they still cannot do
is turn the main protection on: with ufw installed and off (Ubuntu's
default) or firewalld disabled, the firewall plan is refused and the app
only shows the command to type. And nothing guides a new install: most
plugins are off, some need a program that is missing, and the password
and the organisation entry are not explained.

## Progress

- M1 done (2026-11-09): ufw `enable`/`disable` actions, firewalld through
  `systemd.unit`, `enable_manager` in `net.firewall`, the "Turn on the
  firewall" card. `--phase firewall-on` 7/7 on Ubuntu 24.04 (ufw), Arch
  and Fedora (firewalld): turned on over SSH, a new SSH connection gets
  in, rollback and the confirm timeout turn it off. `--phase f5` still
  green on Fedora and Ubuntu. Found on the way: rolling back a firewalld
  the transaction started failed on the reload; fixed.
- M2 done: the Overview lists the `detect.*` notes that carry an install
  command, with a copy button.
- M3 done: the first-run welcome (five steps, five languages), shown once
  per account and from Settings. The e2e suite now starts past it.
- M4 done: `ibexwall-admins`, empty by default, with its polkit rule;
  `--phase desktop` d8 checks it (9/9 on Fedora, Ubuntu 24.04, Arch).
- M5 left: the full matrix and a draft release, after the maintainer has
  checked v0.1.1. Pending: the Playwright suite is not run in CI, which
  let a stale keyboard test through.

## Milestones

1. **M1 Turn on the installed firewall (ADR-0046).** ufw `enable` and
   `disable` actions; rollback converges on the restored `ufw.conf`;
   firewalld through `systemd.unit` on `firewalld.service`; the plan
   (`enable_manager=true`) first allows the listening TCP services. The
   Firewall screen offers "Turn on the firewall" when the manager is off.
   Verify: unit tests for argv, validation and the plan; a VM phase that
   turns it on over SSH and rolls it back, on Ubuntu (ufw) and on a
   distribution with firewalld disabled.
2. **M2 What is missing.** One list of what the enabled and recommended
   plugins need and do not find (nmap, ClamAV, OpenSCAP, chrony, a
   firewall manager), from the plugins' `detect.*` findings, each with
   the install command for this distribution and a copy button. IbexWall
   never installs packages by itself.
3. **M3 The first-run assistant.** Shown once after install (and from
   Settings): what IbexWall does, a first check, what is missing (M2),
   the protections to turn on (one plan, one password), how the password
   prompt works, and the entry for a computer managed by an
   organisation. Every text in the five languages.
4. **M4 An administrators group, off by default.** `ibexwall-admins`, with
   a polkit rule that lets its members change IbexWall without a
   password; the group ships empty, and the assistant explains it
   without adding anyone.
5. **M5 Tests and release.** UI tests per step, the matrix (`desktop`,
   `f10`, the new firewall phase), a draft release, the maintainer's
   check on the KDE VMs.

## Out of scope

Installing packages through PackageKit; the corporate enrollment itself
(the closed plugin); GNOME-specific checks beyond the manual one.

# v0.5: export and import of IbexWall's own state (ADR-0049)

Status: the maintainer accepted ADR-0049 on 2026-11-25 (option 1: one
readable JSON file; option 3 rejected). Backlog: B-03 follow-up.

## What the file holds

- `schema`: 1; `ibexwall`: app version; `exported_at`: RFC 3339.
- `layers`: the user layer (`config.toml`) and the profile layer
  (`profiles.d/active.toml`), parsed, exactly as stored.
- `effective`: the merged settings per plugin, for reading only (the
  import never uses this section: the layers are the truth).
- `plugins`: id, enabled state and note ("the plugin is on the machine"),
  written back on import.
- `restore_points`: name, the transaction it was taken at, and the created
  date, as text. The snapshots do not travel; "go" on a machine without
  them says so plainly (ADR-0048).
- `digest`: SHA-256 over the canonical JSON of the sections above (JCS),
  so a truncated or hand-edited file is caught at import.

What is deliberately not in the file: the transaction log, the snapshots,
the organization layer (`org.toml`, with its locks: those belong to the
organization), any token or hash, and the applied-choice records (the
machine writes those; importing one would claim an applied state the
machine does not have).

## Behaviour

- `ibexctl export [FILE]` (default `ibexwall-state.json`): a read.
- `ibexctl import FILE`: first a dry run is always shown: what would be
  written (settings keys that differ, plugins whose state differs), what
  the organization layer of this machine keeps locked (a locked key stays
  locked), and a note that nothing on the machine changes. `--yes` goes on.
- The import writes the two layers and the plugin states, then the daemon
  reloads its configuration. Organization locks are enforced by the normal
  write path (the layer write refuses a locked key), and the org layer of
  the file is refused outright.
- The API: `ExportState` (POLKIT_READ) and `ImportState` (POLKIT_PLUGINS_MANAGE,
  it changes what the app will do from then on, though not the machine).
- The app gets a Settings section in a later milestone; the file also
  becomes the bridge ADR-0048 option 2 needs.

## Steps

1. **M1 core and CLI** (this plan): the two API methods, the state
   helpers, `ibexctl export|import`, the schema export, unit and e2e
   tests (export, digest check, dry run, import, locked key refused,
   org layer refused).
2. **M2 release**: dependency of nothing else; 0.5.0 draft with the
   EndeavourOS VM (the maintainer's third, 172.22.2.113) smoke-tested.
3. **M3 later**: the Settings section in the app; the snapper/Timeshift
   hook reads this file (ADR-0048 option 2, dormant until now).

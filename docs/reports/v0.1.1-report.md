# v0.1.1 report: the desktop app can change the machine

Date: 2026-11-09. Plan: `docs/plans/v0.1.1-desktop-fixes.md`. Decision:
ADR-0045 (interactive polkit authorization, accepted).

## Why

v0.1.0 installed and ran on Fedora 45 and Ubuntu 26.10 with KDE, but a
person at the desktop could not change anything: every change was refused
with no password prompt. The VM matrix had not seen it because it runs as
root, which polkit allows without asking.

## What was done

- **Interactive authorization (M1, M2).** The methods that change the
  machine take an optional `allowInteractiveAuthentication`, systemd's
  name for the same thing. When it is set, the daemon lets polkit ask the
  session's agent for a password; the check is cancelled when the client
  hangs up (the varlink server now watches the peer during a call) or
  after five minutes. Without it, a change answers the new
  `AuthenticationRequired` error, apart from a refusal. The desktop app
  always sets it, `ibexctl` on a terminal (`--no-ask-password` turns it
  off), the MCP server never.
- **The app says what happens.** A banner shows "waiting for
  authorization" while a change is pending and explains a refusal, a
  missing dialog, a lock or an unreachable service. Several toggles had
  dropped their errors silently; they report them now.
- **The resolver's answers socket (M3).** It never opened in a packaged
  install (the daemon cannot write to the resolver's directory). It moved
  to `/run/ibexwall/answers.sock`, open to the resolver's group only
  (0660); before, every local user could send it answers.
- **Sidebar and status (M4).** Only the content scrolls; the footer
  reports the service (connecting, active, running, partly working, not
  responding, no access) instead of a fixed "Protection active".
- **Organisation (M5).** The screen had no texts at all (message ids on
  screen) and called a method behind an action no person holds.
  `GetEffective` now needs only read and reports `managed`; the screen
  shows only when an organisation manages the machine, with an entry in
  Settings. The locale check now fails when the interface uses a message
  that does not exist.
- **A fresh audit chain** no longer reads as broken.
- **Tests as a person (M6).** `cargo xtask vm-test --phase desktop`: a
  test user, a polkit rule with an active session's defaults and a driver
  that plays the terminal and the agent. Fresh install clean, read
  allowed, a change without the flag asks for authentication, the right
  password lets it through, a wrong one is a refusal, no agent gives no
  dialog.

## Verification

- `cargo nextest run --workspace`: 718 passed. UI: 130 passed;
  `pnpm check`, `lint`, locales and `schemas --check` clean. CI green.
- `--phase desktop`: 8/8 on Fedora, Ubuntu 24.04 and 26.04, Debian, Arch.
- `--phase f10`: 10/10 on the five, after the AppArmor and SELinux
  changes; the deb upgrade test now reads the version from the changelog.
- Release `v0.1.1` built by the workflow (deb, rpm, Arch, tarball, eBPF,
  SBOM, provenance, signatures): **draft**.
- The draft packages upgraded 0.1.0 in place on the maintainer's Fedora 45
  and Ubuntu 26.10 KDE VMs: version 0.1.1, nothing degraded, audit chain
  valid, answers socket 660 ibexwall-dns, no warning at start, no SELinux
  or AppArmor denial.
- From inside the active KDE session (a process placed in the session's
  scope): reading works without a password; a change with
  `--no-ask-password` answers `AuthenticationRequired` under the real
  default policy; a change from a terminal raised KDE's own password
  dialog on both machines (screenshots), and cancelling the request
  closed the dialog and changed nothing.

## Still to do before publishing

A person types the password: in the desktop app, turn on a plugin, the
firewall (firewalld on Fedora, ufw on Ubuntu), add a rule, change DNS,
undo each. Then `gh release edit v0.1.1 --draft=false`, and deploy the
docs (`ibexwall-docs` commit "password prompts for changes").

## Deviations

- The audit chain does not record whether a dialog was shown (ADR-0045
  amended): the app asks on every change, and polkit logs each
  authentication to the journal.
- Test harness: newer polkit (Arch) runs its password helper from
  `polkit-agent-helper.socket`; the desktop phase starts it.

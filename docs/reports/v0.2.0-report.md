# v0.2.0 report: turning protections on, and the first run

Date: 2026-11-10. Plans: `docs/plans/v0.2-first-run.md`. Decision: ADR-0046.
Release: draft `v0.2.0` (deb, rpm, Arch, tarball, eBPF, SBOM, provenance).

## What was done

- **Turn on the installed firewall.** ufw (Ubuntu's default, off) or a
  disabled firewalld is turned on through its own tool, after allowing the
  TCP services listening on every address so SSH survives. The change is
  kept or undone like any other. New typed ufw `enable`/`disable` actions;
  rollback converges on the restored `ufw.conf`; a firewalld the rollback
  stops is not reloaded.
- **What the protections need.** The Overview lists the programs that are
  missing, with the install command for the distribution and a copy button.
- **First-run welcome.** Five steps in five languages, shown once per
  account and from Settings.
- **`ibexwall-admins`.** Empty by default; members change IbexWall without
  a password.
- **Maintainer findings on v0.1.1, all fixed.**
  - Allowing a port did nothing on Fedora Workstation: its zone allows
    1025-65535, so firewalld refused to add the port, the check did not
    find it listed and the change was undone silently. The plan says the
    port is already allowed and by which rule; the CLI prints the reason.
  - Block lists and a changed DNS provider did nothing: the resolver could
    not write its lists (root's directory, reset on every daemon start).
    They live in `/var/lib/ibexwall-dns`. The DNS screen showed defaults
    instead of what is applied; it loads the effective configuration.
  - The connection monitor was never enabled by the package. It runs after
    the install, has a button in Apps and network and `ibexctl apps
    monitor on|off`; an explicit off is kept.
- **CI.** The Playwright flows and accessibility checks now run in CI.

## Found by the matrix on the way

- Removal left the monitor's wants link, and a monitor still running
  restarted after the daemon stopped and pulled the daemon back up
  (`Wants=`). The monitor is stopped first.
- Two nested `StateDirectory` entries made the resolver fail at
  `STATE_DIRECTORY`.
- Test environment: the Arch image is older than the repository (a partial
  `-Sy` conflicted on the split openssl package); the provisioning now does
  a full upgrade that keeps the running kernel, since a new kernel removes
  the running one's modules and breaks every change that loads one.

## Verification

- 725 Rust tests, 141 UI tests, 20 Playwright flows; schemas, locales,
  clippy and fmt clean; CI green.
- `--phase f10` 10/10 on Fedora, Ubuntu 24.04, Ubuntu 26.04, Debian, Arch.
- `--phase desktop` 11/11 (the earlier 8 plus the administrators group, the
  monitor and a block list) on the five.
- `--phase firewall-on` 8/8 on Ubuntu 24.04 (ufw), Fedora and Arch
  (firewalld): turned on over SSH, a new connection gets in, rollback and
  the confirm timeout turn it off, a port inside a range is reported.
- The release packages installed on the maintainer's KDE VMs (Fedora 45,
  Ubuntu 26.10): 0.2.0, nothing degraded, audit chain valid, monitor
  running, no warning at start, no SELinux or AppArmor denial; the range
  case prints its reason.
